## 进度更新准则

- `[ ]` 表示未完成，`[x]` 表示已完成；初次创建时全部开发和验收项保持未勾选。
- 按可独立运行、验证和验收的业务闭环组织，不按前端页面、后端接口、文件数或代码量计算完成度。
- “功能闭环完成”只有在真实实现、必要自动验证、权限验证和真实联调均通过后才能勾选。对应子项未通过时，闭环项不得勾选。
- Mock、占位接口、页面展示、部分实现、测试失败、跳过关键 live 场景或缺少真实依赖均不算完成。
- 自动验证、权限验证、真实联调、最终 Agent QA、用户试用和用户最终验收分别记录，不互相替代。
- 开发中完成一个闭环及时更新本功能对应项；只更新本功能，不改其他功能进度。
- Q01—Q08 的业务规则、运行阶段、桌面支持范围及本轮模型测试预算已确认，详见 PRD 第 15 节；仅每题时限，不设整场上限，全部题目作答结束才起算 24 小时补传。一年留存按北京时间自然周年计算，不按固定 365 天；实际测试账号、环境、模型／存储配额和灾备配置仍需准备核验。方案确认不算实现或验收通过，部分通过不能算整项完成。
- 用户没有明确确认前，“用户最终验收”永远保持未勾选。最终 QA 技能要求见文末强制章节。
